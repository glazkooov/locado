# CLAUDE.md

## Project Overview

Locado — сервис для поиска интересных мест и маршрутов в Москве.

Это НЕ карта, НЕ справочник организаций и НЕ аналог Яндекс Карт.

Главная идея проекта:

Пользователь не знает, куда пойти сейчас.

Locado помогает выбрать место или маршрут под настроение, ситуацию и интерес.

Примеры запросов:

* Куда сходить на свидание?
* Где спокойно погулять вечером?
* Куда выбраться в выходные?
* Где сделать красивые фотографии?
* Как провести день в Москве необычно?

---

## Product Principles

### 1. Inspiration First

Главная задача проекта — вдохновлять пользователя.

Мы не строим каталог заведений.

Мы показываем идеи для отдыха.

---

### 2. Curated Content

Каждое место должно выглядеть как рекомендация друга.

Избегать сухого энциклопедического описания.

Плохо:

"Парк основан в 1954 году и занимает площадь 17 гектаров."

Хорошо:

"Одно из лучших мест для неспешной прогулки среди старых деревьев и тихих аллей."

---

### 3. Human Tone

Тон общения:

* дружелюбный
* живой
* лёгкий
* современный

Не использовать:

* канцелярит
* официальный стиль
* рекламные штампы
* чрезмерный маркетинг

---

### 4. Decision Simplicity

Пользователь должен быстро принять решение.

Не перегружать интерфейс.

Минимизировать количество действий.

---

## Target Audience

Возраст:

18–35 лет

Основные сценарии:

* прогулки
* свидания
* встречи с друзьями
* фотография
* культурный отдых
* поиск новых впечатлений

---

## Design Principles

### Общий стиль

Интерфейс должен ощущаться:

* современным
* лёгким
* атмосферным
* визуально дорогим

Не использовать:

* перегруженные блоки
* тяжёлые таблицы
* сложные панели управления

---

### Visual Priorities

Приоритет элементов:

1. Атмосферная фотография
2. Название места
3. Краткое описание
4. Практическая информация

---

### Mobile First

Все изменения проверять в первую очередь на мобильных устройствах.

Ширины:

* 375px
* 390px
* 430px

Не допускать:

* горизонтального скролла
* налезания текста
* сломанных карточек

---

## Current MVP Scope

В MVP входят:

* Главная страница
* Категории
* Подборки
* Карта
* Страницы мест
* Поиск

Не входят:

* Личный кабинет
* Авторизация
* Избранное
* Социальные функции
* Комментарии
* Чат

Не предлагать добавление этих функций без отдельного запроса.

---

## Content Categories

Использовать следующие категории:

* Еда и напитки
* Природа
* музеи
* Театры
* Фото
* Развлечения

Не создавать новые категории без необходимости.

---

## Development Rules

Перед внесением значительных изменений:

1. Провести анализ текущего решения.
2. Составить список предлагаемых улучшений.
3. Объяснить причины изменений.
4. Дождаться подтверждения пользователя.
5. Только после подтверждения менять код.

---

## Code Quality

При работе с кодом:

* избегать дублирования
* использовать понятные названия переменных
* писать читаемый HTML
* минимизировать сложность JavaScript
* не добавлять зависимости без необходимости

Предпочитать:

* HTML
* CSS
* Vanilla JavaScript

Перед предложением фреймворков объяснять их необходимость.

---

## UI Change Policy

Запрещено без согласования:

* менять визуальную концепцию
* менять структуру главной страницы
* полностью перерабатывать дизайн
* удалять существующие разделы

Разрешено:

* улучшать UX
* улучшать адаптивность
* улучшать производительность
* улучшать доступность
* исправлять баги

---

## Review Mode

Если пользователь просит провести ревью:

1. Сначала предоставить список замечаний.
2. Разделить замечания на:

   * критические
   * желательные
   * косметические
3. Предложить конкретные изменения.
4. Не менять код до получения подтверждения.

---

## Main Goal

Каждое изменение должно делать проект более похожим на настоящий городской сервис рекомендаций и вдохновения, сохраняя текущую концепцию, структуру и визуальный стиль.
