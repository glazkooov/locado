# Telegram-автоматизация в Codex

10.11.2026 владелец проверил отправку трёх черновиков и разрешил включить
оба расписания. Задачи созданы и включены в Codex Automations. Параметры
и ID находятся в `tools/automation/telegram-routines.json`; фактическое
состояние проверяется через automations.peek. Перед изменением ищи эти
задачи, не создавай новые с теми же действиями.

| Задача | Время по Москве | Первый запуск |
|---|---|---|
| Три черновика в личку | 09:37 каждый день | 11.11.2026 |
| Недельный разбор в личку | 10:41 по понедельникам | 16.11.2026 |

Часовой пояс Europe/Moscow, UTC+3 без сезонного перевода. Задачи заданы
как exact_schedule с DTSTART в этом часовом поясе. Возможны задержки начала
запуска. Исторические пропуски и старые разовые публикации не догонять.

## Исполнение и разрешения

Планировщик запускает агента с унаследованной средой чата locado.
Рабочий checkout `/workspace/locado`, единственная ветка состояния
`claude/telegram`. Новая среда может открыть main: сначала получить свежую
claude/telegram и безопасно перейти на неё. Инструкции пока могут быть
только в этой ветке; PR #132 в main не сливается автоматически.

Ежедневное задание: `tools/automation/daily.md`. Агент выбирает тему
по текущему плану, пишет текст, проверяет humanizer и preview, отправляет
три черновика владельцу с пометками утро/день/вечер и сохраняет журнал.
Сам `pick` текст не пишет. Готовые сегодня слоты не отправлять повторно.

Недельное: `tools/automation/weekly.md`, команда
`node --use-env-proxy tools/telegram-stats.mjs --send`. Публичное превью
канала даёт просмотры и подписчиков; API Метрики не используется. Небольшие
числа не позволяют надёжно сравнивать эффективность рубрик.

Пользователь разрешил штатные отправки в личку 10.11.2026. Новое
подтверждение для каждого запуска не нужно. Публикация в канал остаётся
только по отдельному актуальному указанию владельца.

## Среда и секреты

- Node.js 22+, Playwright/Chromium для схем и альбомов; установка и
  активация по docs/development.md. Для обычных текстов/фото рендер не нужен.
- `TELEGRAM_BOT_TOKEN` берётся только из Secrets среды, разрешённый host
  api.telegram.org. Значения вводятся в настройках, не в чате и не в Git.
- Для HTTP-запросов из Node нужен `--use-env-proxy`. Проверка без отправок:
  `node --use-env-proxy tools/cloud/check-telegram.mjs`.
- 10.11 подтверждены getMe бота @locado_help_bot, разовая доставка трёх
  постов и трёх пометок в личку, Git read/write claude/telegram и HTTP 200
  публичного превью t.me/s/locado_msk. Отдельный пробный недельный отчёт
  вручную не отправлялся; первый штатный разбор запланирован на 16.11.
- tools/telegram.json уже содержит личку владельца и @locado_msk.
  Не повторяй setup для штатного запуска. Права публикации в канал этой
  проверкой не подтверждались и для отправок в личку не нужны.
- TEST_FTP_* относятся только к тестовому сайту; отдельный GitHub PAT,
  токен Метрики или GitHub Actions secret для этих задач не требуется.

Не печатай токен, URL с ним, окружение или сырые ошибки fetch. Используй
безопасные метаданные ошибок и подтверждений доставки.

## Один писатель состояния

Перед ежедневной, недельной и ручной отправкой:

```bash
node tools/automation/state-lock.mjs acquire daily
# Для недельной задачи вместо daily: weekly; для ручной: manual.
```

Скрипт атомарно занимает Git-ref `refs/heads/codex/locado-telegram-state-lock`
через обычный push уникального корневого коммита с пустым деревом. Чужая
блокировка не может быть fast-forward: второй запуск не получит её.
Ни force-push, ни локальный flock между разными средами не используются.
Локальная квитанция владельца хранится внутри .git, секретов в ней нет.
Блокировка получается один раз на запуск. Если этот запуск уже получил
daily/weekly по prompt, повторять acquire при чтении навыка не нужно.

Под блокировкой снова получи свежие main и claude/telegram, проверь чистоту
дерева, внеси main без reset/force и прочитай актуальное состояние. Иначе
между первоначальным fetch и захватом блокировки другой агент мог успеть
сохранить новые отправки. При занятой блокировке не отправляй ничего.

После успешного сохранения и push либо остановки до любых отправок:

```bash
node tools/automation/state-lock.mjs release
```

`status` показывает занятость и принадлежность. Освободить
чужую блокировку скрипт не позволяет. Зависшая блокировка автоматически
не истекает: сначала проверить прежний запуск и фактическую доставку.

## Сбой и повторный запуск

При успешной отправке и сбое Git push восстанавливай только Git-запись.
Не отправляй сообщения снова. До отправки сохраняй ID темы/слота, после
неё безопасное подтверждение Bot API. Недельный snapshot пишется до send
и сам по себе доставку не доказывает. При неизвестном результате POST
не повторяй --send автоматически; оставь блокировку и свидетельства для
восстановления. Это не транзакция отправки и Git-коммита.

## Другие автоматизации

GitHub workflows photos.yml и deploy-test.yml обслуживают фото и тестовый
сайт. Они не запускают Telegram-задачи. Production владелец публикует
вручную. Тестовый FTP-деплой может сработать от push claude/**;
сам workflow не запускает npm run check.
