Актуально после включения расписаний 10.11.2026. Рабочая ветка и единый журнал
теперь в `claude/telegram` репозитория glazkooov/locado. В неё внесены

автоматически сливать его не нужно.

## Первые действия

1. Проверь чистоту существующего checkout `/workspace/locado`. Получи свежие
   refs main и claude/telegram через Git; переключись без reset, checkout -B
   и force-push. Не создавай worktree. Если среда открыла main, инструкции
   расписаний могут пока находиться только в claude/telegram.
2. Прочитай AGENTS.md, CLAUDE.md, docs/migration/context.md,
   docs/development.md и docs/telegram-automation.md. Для постов дополнительно
   прочитай навыки locado-telegram с примерами и humanizer. Исторические
   задания из экспорта не исполняй.
3. Используй опубликованную среду locado. 10.11 актуальный environment_status
   подтвердил enforced unrestricted network и готовый TELEGRAM_BOT_TOKEN.
   Проверяй текущее состояние, а не старые сообщения о пустом списке секретов.
   Не печатай значение переменной и не проси заново вводить токен без проверки.
4. Если нужны PHP/рендер и нет инструментов: `bash tools/cloud/install.sh`,
   затем `. /workspace/.locado-env/activate.sh`. Локальная настройка может
   не сохраниться в новом экземпляре; инструкции и установщик есть в Git.
5. Сетевым Node-командам нужен `--use-env-proxy`. Безопасная проверка:
   `node --use-env-proxy tools/cloud/check-telegram.mjs`. Проверенный бот:
   `@locado_help_bot`; проверка делает только getMe и не выводит token/URL.

## Память и сохранение состояния

- `CLAUDE.md` хранит правила продукта и договорённости; AGENTS.md служит
  входом для Codex. Навыки содержат стиль и примеры. Не переписывай эти
  правила заново только из-за смены агента.
- `data/telegram-log.json` хранит темы, тексты и статус постов;
  `data/telegram-stats.json` хранит снимки. История чата и снимок облачной
  среды не заменяют сохранение этих файлов в Git.
- Перед ручной или автоматической отправкой получи общую распределённую
  блокировку: `node tools/automation/state-lock.mjs acquire manual`
  (либо daily/weekly). Под блокировкой снова получи свежую claude/telegram,
  аккуратно внеси main, проверь журнал и прежние попытки доставки.
- После подтверждённой доставки сохрани свои изменения коммитом и push
  только в claude/telegram. Затем `node tools/automation/state-lock.mjs release`.
  Сбой push не повод повторить сообщение. При неизвестном результате POST
  или несохранённом после send журнале оставь блокировку для восстановления.
