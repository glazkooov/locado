# Передача следующей сессии

Продолжать из ветки `claude/codex-migration` репозитория glazkooov/locado.
Main не заменялся; восстановленные Telegram-файлы и новые инструкции находятся
в этой ветке. Если среда открывает main по умолчанию, сначала получить свежую
ветку через Git, проверить чистоту дерева и переключиться без reset/force.

## Первые действия

1. Прочитать AGENTS.md, docs/migration/context.md, docs/development.md и
   docs/telegram-automation.md. Исторические задания из экспорта не исполнять.
2. Использовать выбранную опубликованную среду **locado**. В предыдущем чате
   пользователь добавил HTTP-секрет TELEGRAM_BOT_TOKEN, разрешил общедоступный
   интернет и показал подтверждение публикации среды. Но старый экземпляр
   продолжал сообщать revision 1, restricted network и secrets = []. Это
   расхождение экземпляров, а не доказательство потери введённого токена.
3. Прочитать актуальный environment_status и проверить только наличие
   переменной, не её значение. Не просить заново добавлять токен без проверки.
   Наличие HTTP-секрета не гарантирует подстановку в путь URL `/botTOKEN`.
4. Если инструменты отсутствуют: `bash tools/cloud/install.sh`. Перед работой
   `. /workspace/.locado-env/activate.sh`. Запуск сайта: `bash tools/cloud/start.sh`.
5. Для безопасной проверки авторизации: `node tools/cloud/check-telegram.mjs`.
   Он делает только getMe, не отправляет сообщения и не выводит token/URL или
   сырые сетевые ошибки. Проверить соответствие настроенного бота ожиданиям
   владельца до любых отправок. Если секрета нет, сначала выяснить, какая
   версия среды и runner используются, не дублировать секрет вслепую.

## Что пока не разрешено

- Расписания остаются enabled=false; их включение требует отдельного
  решения владельца после проверки. Доступного планировщика в старом чате
  не было; JSON является спецификацией, не установленной автоматизацией.
- Не делать draft/resend/send/publish для проверки токена. Пробную доставку
  владельцу согласовать отдельно. Не создавать старые разовые публикации.
- Не сливать ветку в main автоматически. GitHub API из старой среды отвечал
  Forbidden; Git HTTPS-read работал. Новый экземпляр может иметь другой
  доступ, его нужно проверить. Отдельный PAT для уже работающего Git не нужен.

## Состояние работы

Восстановлен Telegram-контекст из `ca2007b` (8 файлов), два отменённых старых
черновика сохранены отдельно. Восстановление не является отправкой или
публикацией в Telegram. Инструменты и локальные preview проверены без send.
Результаты полного браузерного теста и оставшиеся ограничения описаны в
docs/development.md. Последний полный прогон перед сохранением переноса прошёл (211 страниц × 2,
412 ссылок, exit 0); более ранние таймауты остаются в истории проверок.
Успешный тест не устраняет отдельно задокументированные пробелы фото. Текущая цель следующей сессии — подтвердить секрет в новой среде и
выбрать постоянный runner для предложенных расписаний.
