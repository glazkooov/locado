# Разработка и проверка Locado в облаке

Проверено в этой среде 10.11.2026: Debian 13 x86_64, Node 24.22.1,
PHP 8.4.27, GD с FreeType и mbstring, системный Chromium 156.
Приложение без сборки и npm-зависимостей; `npm install` в корне не требуется.
Node 22+ нужен инструментам (в частности `Object.groupBy` в статистике).

## В следующей сессии

Использовать существующий checkout `/workspace/locado`; задача уже изолирована,
новый worktree не создавать без запроса. Прочитать AGENTS.md и CLAUDE.md.

Из корня репозитория:

```bash
bash tools/cloud/install.sh
. /workspace/.locado-env/activate.sh
bash tools/cloud/start.sh
```

Последняя команда работает в переднем плане долгоживущей сессии. Снимок среды
не сохраняет работающий процесс, после восстановления PHP запускается заново.
По умолчанию используется порт 8766, другой: `LOCADO_PORT=8767 bash tools/cloud/start.sh`.
Не занимать 8790: его использует `npm run check`. Проверки не запускать
одновременно на одном порту. Для локальных запросов не создавать web-preview.

В другой оболочке, после активации:

```bash
curl -fsS http://127.0.0.1:8766/ -o /tmp/locado-home.html
curl -fsS http://127.0.0.1:8766/place/neskuchny-sad -o /tmp/locado-place.html
curl -fsS 'http://127.0.0.1:8766/api/og-image.php?place=neskuchny-sad' -o /tmp/locado-og.jpg
file /tmp/locado-og.jpg
npm run check
```

Ожидается HTTP 200; OG — JPEG 1200×630. `npm run check` проверяет данные,
актуальность CSS и preload, JS, отсутствие горизонтальной прокрутки,
экраны «не нашли», внутренние ссылки, все страницы на 390 и 1280 px.
`--quick` проверяет только телефон и не заменяет полный прогон.
Генераторы CSS/preload/sitemap запускаются после соответствующих изменений
по CLAUDE.md; для одной настройки среды они не нужны.

## Что делает установщик

`tools/cloud/install.sh` повторяемо создаёт служебные файлы вне checkout:
`/workspace/.locado-env` и ссылку Playwright в `/workspace/node_modules`.
Скачивает Debian-пакеты PHP из официальных репозиториев через apt, с проверкой
подписей индексов и контрольных сумм пакетов. Распаковывает их локально,
не требует sudo и не меняет системные пакеты, manifest или lockfile проекта.
`Debug::NoLocking` применяется только к download-only, не отключает подписи.
PHP использует локальный загрузчик библиотек и расширения GD/mbstring.
Скрипт рассчитан на этот Debian 13 x86_64 image, не универсален для Mac/Windows.

Playwright берётся из установленного модулем образа. Если его или системного
`/usr/bin/chromium` нет, установщик завершится ошибкой; не отключать проверку
TLS и не подменять пакеты. Активация добавляет внешний Node preload-адаптер,
выбирающий системный Chromium. Исходники тестов не изменяются, проверки не
отключаются. После активации адаптер применяется и к рендеру Telegram-картинок.

Это рабочий обход недоступной загрузки браузера, **не подтверждённая
совместимость версий**: установленный Playwright ожидает Chromium 151,
образ предоставляет Chromium 156. Не выдавать это за доказанную причину
таймаутов. Для штатного браузера нужен `cdn.playwright.dev`; попытка загрузки
вернула 403 Domain forbidden. Если после разрешения этот host перенаправит
запрос, добавлять только фактически установленные redirect-hosts.
Проверить доверенную загрузку и удалить системный адаптер из активации
перед проверкой штатной версии; затем повторить полный тест.

## Что именно мешает публикации

Публикация сайта на Beget, тестовый FTP-деплой и публикация снимка облачной
среды — три разных операции. У них нет общего автоматического блокиратора.

| Область | Подтверждённый результат | Что блокирует |
|---|---|---|
| Приложение / smoke | Главная, страница места и данные отвечают 200; браузер открывает главную и место; OG JPEG 1200×630 | По этим проверкам блокера нет, это не проверка всех функций production |
| Генерация ресурсов | `stalePreloads()` и `staleCss()` вернули пустые списки | По актуальности CSS/preload блокера нет |
| Полный `npm run check` | Последний прогон перед сохранением переноса: **exit 0**, 179 мест, 25 подборок, 211 страниц × 2, 412 ссылок. Два более ранних прогона: exit 1, 6 и 5 desktop navigation timeout по 30 секунд | Последний обязательный прогон пройден; прежние таймауты остаются свидетельством нестабильности, причина не установлена |
| Изолированные повторы | Все 11 страниц с таймаутами прошли отдельно: 200, без JS-ошибок, прокрутки и экрана «не нашли» | Это свидетельство нестабильности полного прогона, не зелёный полный тест и не доказательство отсутствия багов |
| Фото / приложение | `check-photos.mjs`: 104 отсутствующих файла, 47 ссылок на главную mos.ru, всего 151 | Отсутствующие фото — реальный пробел контента; страницы имеют fallback. Для выпуска с обещанными фото нужно добавить файлы или осознанно выбрать вариант без них. 47 общих ссылок — рекомендация, не поломка и не отсутствие авторства |
| Сезонные данные | Блок есть на каждый день года; 24 предупреждения `story.when`, используется описание | Редакционная доработка, сама по себе не блокирует запуск |
| Сохранение среды | Чтение cloud draft дважды и запись install_script/start_skill вернули INVALID_ARGUMENT; запись не подтверждена | Блокирует утверждение «конфигурация облачной среды сохранена», не публикацию приложения на Beget |
| Загрузка браузера | 403 Domain forbidden на cdn.playwright.dev | Блокирует проверку на штатном браузере Playwright, не работу сайта в браузерах посетителей |

Первый прогон был с лишней параллельной нагрузкой; второй без неё тоже дал
таймауты, на других страницах. Поэтому одной нагрузкой проблему объяснить
нельзя. Перед сохранением переноса в Git выполнен ещё один полный прогон: он
завершился **exit 0**, «Проблем нет». Тесты и их таймауты не менялись. Один
успешный прогон не доказывает, что прежняя нестабильность устранена.

Подробности фото: `node tools/check-photos.mjs` и `docs/photos.md`.
**Этот скрипт печатает замечания, но не выставляет ненулевой exit code**:
код 0 не означает, что все фото прошли. Не использовать его как машинный
release gate без отдельной доработки. Отсутствующие файлы не появляются
после запуска photos.py: он только обрабатывает уже существующие.

В `.github/workflows/deploy-test.yml` нет вызова тестов: push `claude/**`
может обновить тестовый сайт даже при красном npm check. Без `TEST_FTP_*`
деплой пропускается. Production владелец загружает вручную. Ни приложение,
ни workflow не проверяют сохранение cloud draft; это независимый слой.

## Что проверено при переносе Telegram

- Восемь восстановленных файлов сверены с `ca2007b`; приложение не менялось.
- Синтаксис Telegram-скриптов, `pick today`, `preview` существующего черновика
  «Артплей», форматирование заголовка и лимит подписи; никаких сетевых send.
- Журнал: 24 уникальных ID, 3 снимка; старые исключённые черновики в архиве.
- Установщик и стартовый helper запускаются из checkout; install smoke
  проверяет PHP и запуск Chromium. Полный browser suite остаётся отдельным.
- Токена Telegram нет, доставка и права бота не проверялись.

Проверка только авторизации в новой среде: `node tools/cloud/check-telegram.mjs`.
Команда делает read-only `getMe`, не печатает токен и не отправляет сообщения.
При отсутствии переменной завершится кодом 1; это не ошибка самого бота.
Передача следующей сессии: `docs/migration/next-session.md`.

Файлы `tools/cloud/*` и эта инструкция живут в проекте и позволяют повторить
настройку без утрачиваемых ссылок на `/workspace/.locado-env/install.sh`.
Облачные `install_script`/`start_skill`, snapshot и публикация среды не
считаются сохранёнными только из-за существования этих файлов.
