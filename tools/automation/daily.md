# Ежедневное агентное задание

Включено владельцем 10.11.2026, ежедневно в 09:37 Europe/Moscow,
первый запуск 11.11.2026. Цель: три черновика в личку, без публикации в канал.
Три черновика за 10.11 уже доставлены, повторять их не нужно.
Блокировку захватывай один раз на запуск: если её уже получил этот же
запуск по prompt автоматизации, не повторяй acquire из инструкции или навыка.

1. Прочитай AGENTS.md, CLAUDE.md, docs/telegram-automation.md,
   docs/telegram.md, docs/telegram-plan.md, актуальный навык
   .claude/skills/locado-telegram/SKILL.md и его references/examples.md.
   Для текстов используй существующий humanizer. Работай в существующем
   checkout, новый worktree не создавай. Подключи окружение по docs/development.md.
2. Получи распределённую блокировку:
   `node tools/automation/state-lock.mjs acquire daily`. Если она занята или
   результат неизвестен, ничего не отправляй. Проверь Git status, сохрани чужую работу.
   Получи свежие main и claude/telegram через платформенный HTTPS Git-доступ;
   используй согласованную ветку claude/telegram. Без reset/checkout -B и
   force-push. Перед записью аккуратно внеси main; конфликт не решай наугад.
   Синхронизируй ветки заново уже под блокировкой. При недоступном Git или
   несогласованном журнале не отправляй черновики. Обычная локальная блокировка
   файла не заменяет распределённую: задачи могут работать в разных средах.
3. Определи сегодняшнюю дату по Москве. Проверь журнал: уже подготовленные
   сегодня три черновика не отправляй повторно. При частичном выполнении
   сначала выясни доставленные слоты. Пропущенные дни не догоняй.
4. Первый пост по текущей дате контент-плана, если даты нет — по недельному
   ритму. Второй и третий через `node tools/telegram.mjs pick today` или
   `pick fact`. Утро/день/вечер, без повторения категории; вечерняя тема
   должна подходить для вечера. Не подменяй «Место недели» вторым таким
   постом. Соблюдай 8/6 недель и ссылочные упоминания в опубликованных постах.
5. При старом черновике перечитай нынешние данные сайта перед resend:
   удалённые факты не возвращать. Сверь сезон, доступность, цены и ссылки.
   Отменённые и архивные черновики не отправляй. Текст только из текущих
   данных сайта, голос и структура по навыку, фото только с подписью.
6. Создай JSON вне репозитория, проверь текст humanizer и выполни
   `node tools/telegram.mjs preview /путь/post.json`. Посмотри сгенерированные
   картинки. Preview проверяет формат, но не все факты и не качество текста.
7. Включение и отправки в личку разрешены владельцем. Отправь через
   `node --use-env-proxy tools/telegram.mjs draft /путь/post.json --note утро` (затем день,
   вечер). Для существующего согласованного черновика: `resend <id> утро`.
   Никаких publish, republish, send channel, edit, timer-публикаций или --force.
8. Сохрани только свои изменения data/telegram-log.json коммитом в выбранную
   ветку, без зеркального push во вторую ветку. При сбое push после доставки
   повторяй сохранение, не send. Если доставка после POST неизвестна, не
   повторяй автоматически. Коротко отчитайся владельцу: темы, слоты,
   фактическая доставка, Git-коммит или конкретный сбой, без секретов.
9. После успешного push либо остановки до любых отправок освободи блокировку:
   `node tools/automation/state-lock.mjs release`. При неизвестной доставке
   или несохранённом после отправки журнале оставь блокировку для восстановления.

Сетевым Node-командам нужен `--use-env-proxy`; проверка бота:
`node --use-env-proxy tools/cloud/check-telegram.mjs`. Не печатай сырые
исключения сетевых команд: они могут содержать URL с токеном. Сохраняй безопасные
подтверждения Bot API и результаты попыток, а не только snapshot файлов.
