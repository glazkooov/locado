# Недельное задание

Включено владельцем 10.11.2026, понедельник 10:41 Europe/Moscow,
первый запуск 16.11.2026. Прочитай AGENTS.md, docs/telegram-automation.md
и docs/development.md. Существующий checkout, без нового worktree.
Блокировку захватывай один раз на запуск: если её уже получил этот же
запуск по prompt автоматизации, повторный acquire не нужен.

1. Получи общую распределённую блокировку:
   `node tools/automation/state-lock.mjs acquire weekly`. Если она занята
   или результат неизвестен, ничего не отправляй. Свежие main
   и согласованная claude/telegram; чистое состояние, без reset/force-push.
   Синхронизируй ветки заново под блокировкой. Конфликт журнала или неизвестный
   статус предыдущего send — остановиться. Локальная блокировка файла
   не заменяет распределённую между изолированными средами.
2. Проверь существующий недельный снимок и результат предыдущего запуска.
   Если отчёт уже доставлен за этот понедельник, повторно не отправляй.
   Snapshot сам по себе доставку не доказывает; нужны результат runner и
   подтверждение Bot API. Пропущенные недели автоматически не догоняй.
3. Выполни из корня репозитория:
   `node --use-env-proxy tools/telegram-stats.mjs --send`. Не печатай токен, URL с ним,
   окружение или сырые секретные ошибки. Скрипт пишет снимок до отправки;
   при сетевой неопределённости сначала выясни доставку, не повторяй вслепую.
4. Сохрани только свой data/telegram-stats.json коммитом в выбранную ветку.
   Сбой push не повод снова отправлять сводку. Сообщи результат и commit.
5. Выводы о рубриках делай только при устойчивой картине за несколько недель;
   при малых числах не объявляй победителей и не обещай рост. Скрипт читает
   публичное превью, не закрытую Telegram-аналитику и не API Метрики.
6. После успешного push либо остановки до любых отправок освободи блокировку:
   `node tools/automation/state-lock.mjs release`. При неизвестной доставке
   или несохранённом после отправки snapshot оставь блокировку для восстановления.
