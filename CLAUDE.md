# CLAUDE.md

## Project Overview

Locado — сервис для поиска интересных мест и маршрутов в Москве.

Это НЕ карта, НЕ справочник организаций и НЕ аналог Яндекс Карт.

Главная идея проекта:

Пользователь не знает, куда пойти сейчас.

Locado помогает выбрать место или маршрут под настроение, ситуацию и интерес.

Примеры запросов:

* Куда сходить на свидание?
* Где спокойно погулять вечером?
* Куда выбраться в выходные?
* Где сделать красивые фотографии?
* Как провести день в Москве необычно?

## Product Principles

### 1. Inspiration First

Главная задача проекта — вдохновлять пользователя.

Мы не строим каталог заведений.

Мы показываем идеи для отдыха.

---

### 2. Curated Content

Каждое место должно выглядеть как рекомендация друга.

Избегать сухого энциклопедического описания.

Плохо:

"Парк основан в 1954 году и занимает площадь 17 гектаров."

Хорошо:

"Одно из лучших мест для неспешной прогулки среди старых деревьев и тихих аллей."

---

### 3. Human Tone

Тон общения:

* дружелюбный
* живой
* лёгкий
* современный

Не использовать:

* канцелярит
* официальный стиль
* рекламные штампы
* чрезмерный маркетинг

Обращение и голос:

* к пользователю — на «ты»: «попробуй другое слово», «напиши нам», «загляни ещё»
* в заголовках и предложениях — инклюзивное «мы»: «Куда пойдём сегодня?», «Посмотрим все места?»
* описания мест — безлично, без обращения и повелительного наклонения: «Часы работы лучше уточнить на сайте», а не «уточняйте»
* одно слово для одной вещи: «места» (не «локации», не «заведения»); исключение — категория «Фотолокации»
* ошибки — по-человечески и с выходом: «Не получилось загрузить места. Обнови страницу — обычно помогает»
* эмодзи — не больше одного и только по радостному поводу
* не обещать сроков и не писать чисел, которые устареют («каждую неделю», «больше двадцати мест»)

---

### 4. Decision Simplicity

Пользователь должен быстро принять решение.

Не перегружать интерфейс.

Минимизировать количество действий.

## Design Principles

### Общий стиль

Интерфейс должен ощущаться:

* современным
* лёгким
* атмосферным
* визуально дорогим

Не использовать:

* перегруженные блоки
* тяжёлые таблицы
* сложные панели управления

---

### Visual Priorities

Приоритет элементов:

1. Атмосферная фотография
2. Название места
3. Краткое описание
4. Практическая информация

---

### Mobile First

Все изменения проверять в первую очередь на мобильных устройствах.

Ширины:

* 375px
* 390px
* 430px

Не допускать:

* горизонтального скролла
* налезания текста
* сломанных карточек

## Development Rules

Перед внесением значительных изменений:

1. Провести анализ текущего решения.
2. Составить список предлагаемых улучшений.
3. Объяснить причины изменений.
4. Дождаться подтверждения пользователя.
5. Только после подтверждения менять код.

---

## Code Quality

При работе с кодом:

* избегать дублирования
* использовать понятные названия переменных
* писать читаемый HTML
* минимизировать сложность JavaScript
* не добавлять зависимости без необходимости

Предпочитать:

* HTML
* CSS
* Vanilla JavaScript

Перед предложением фреймворков объяснять их необходимость.

1. Сначала предоставить список замечаний.
2. Разделить замечания на:

   * критические
   * желательные
   * косметические

4. Не менять код до получения подтверждения.

## Работа с владельцем проекта

Договорённости из прошлых сессий — соблюдать без напоминаний.

* Общение — на «ты», живо, без канцелярита; эмодзи — не больше одного.
  Без глаголов мужского или женского рода о владельце («сделал», «нашла»):
  пол не указан.
* Тексты, которые пишет Claude (описания мест, подборки, подписи), —
  черновики: владелец их правит.
* К каждой визуальной правке — скриншот (телефон, а если менялся
  компьютер — и он).
* Не перечислять, какие файлы загрузить на хостинг: владелец знает сам.
* ИНН оператора нигде не показывать.
* Пулреквест — только по просьбе. Работа идёт в ветке `claude/…`;
  test.locado.ru обновляется сам из веток `claude/**`, основной сайт
  владелец загружает на Beget вручную.
* Прототип — сначала прототипом (артефакт или вариант на тестовом сайте
  за параметром), на сайт — после выбора.

## Контент

* Каждое новое место проверять по первоисточнику: официальный сайт, а если
  его нет — официальный Telegram или VK. Если часов там нет — карточка в
  Яндекс Картах (2ГИС из облака не открывается). Поиском только находить
  страницу; выдача поиска источником не считается. Проверить адрес, метро,
  часы, телефон, сайт и что место работает. Координаты — по адресу.
* Описания — своими словами; чужие тексты и посты не копировать.
* Часы — в `schedule`, а не в описании. В текстах не привязываться к
  месяцу или дате, которые устареют («в ноябре», «до 29 ноября»).
* Тип места (`type`) — короткий: он стоит плашкой на карточке и не должен
  обрезаться («Фотолаборатория», а не «Фотолаборатория и пространство»).
* Не предлагать: цирк, речные круизы, каток, боулинг, VR-клубы.
* Тексты для сайта (описания, подборки, подписи) проверять скиллом
  `humanizer` (`.claude/skills/humanizer`, источник — github.com/blader/humanizer,
  версия 8c307f3). Его примеры английские, приёмы те же и в русском:
  «не X, а Y», фраза-концовка, повторяющая мысль, тройки ради ритма,
  рекламные слова («уютный уголок», «в самом сердце»), пустые обороты.
* Тире (§8 скилла): в неофициальном русском фразы, построенные на тире
  («Коломенское — это…», «Здесь всё просто — …»), читаются шаблонно. Такие
  конструкции избегать и переписывать проще. Тире, без которого фраза
  ломается или становится неграмотной, — оставлять; до абсурда не доводить.

## Как устроен проект

* Статический сайт: HTML, CSS, ES-модули без сборки. PHP на Beget — только
  в `api/` и в `place/index.php`, `collection/index.php`.
* Данные: `data/places.json` (места), `data/collections.json` (подборки:
  `type` — `route` или `occasion`; блоки `text`, `place`, `walk`),
  `data/now.json` (блок «Сейчас»). Схема места — в первых записях
  `places.json`; `alsoIn` — вторая категория, `story` — тексты для «Сейчас».
* Адреса: `/place/<slug>` и `/collection/<slug>` (правила в `.htaccess`,
  старые `?slug=` переадресуются). PHP вписывает в HTML заголовок,
  описание и картинку превью (`api/og.php`); картинку 1200×630 рисует
  `api/og-image.php` и кладёт в `api/og-cache/`.
* У страниц места и подборки `<base href="/">` — сайт должен лежать в
  корне домена.
* После изменения списка мест или подборок — `node tools/sitemap.mjs`.

## Проверка перед коммитом

`npm run check` (то же — `node tools/check.mjs`): данные, все страницы
мест и подборок на телефоне и компьютере, ошибки скриптов, горизонтальная
прокрутка, внутренние ссылки. Печатает только итог и найденные проблемы.
Нужны PHP и Playwright (в облачной среде уже есть).
